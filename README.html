What is live, and what is a draft?

The public app fetches data/published.json. The supplied WinterLeague 2026-2027 Team List.xlsx is baked into this local file: 45 populated teams (IDs 2 to 46), 134 player entries and 133 distinct canonical names, with no imported scores or final results. Workbook order and IDs are preserved, including Team 21 first. Number-only rows 1 and 47 to 50 are unused placeholders. Chris Mahon and David Brown have trailing spaces trimmed; original spellings, initials, Brian O'Reilly's curly workbook apostrophe and surname-first Leonard, Dean are otherwise preserved. Score cells were empty and cached totals zero. The source workbook is unchanged.

The app opens the published Team leaderboard: rank, team number and players, team points and weekend points. Without qualifying results it shows No results uploaded yet, not invented first-place ties. Team-list questions are collapsed, while unmatched or held uploaded cards stay visible for review. Singles remains one click away; More: team list, final and committee tools contains secondary views.

Choose Upload HandicapMaster results directly on the leaderboard. Select your result and optional scorecard CSVs together for automatic preview. Review actual player/team matches and matched/unmatched/held counts. Supported report dates and explicit competition/round names fill automatically; a dated weekend name is offered when only a date is available. Supply missing essentials, confirm reported 12-hole net points, then choose Update leaderboard. The recalculated leaderboard appears immediately. Updates are Saved on this device, not shared automatically. Recognized gross scorecards are listed and excluded from net scoring, not stored. Only-scorecard selections need a net report; malformed/unknown result files block the batch with filename-specific errors. Preview creates no draft and saves nothing. Reload opens published view with Resume my saved results when local scores exist.

More: team list, final and committee tools > Committee tools > Edit team list has a team selector, player fields and notes. Select a team or add a new three-player team, then choose Save team to my draft. Existing IDs stay fixed. Edits do not rename/delete raw cards; genuinely different names can leave older cards unassigned. Changes apply across all weekends. Invalidating existing final cards blocks an edit instead of deleting cards. CSV replacement is expandable below the editor. Other imports in the shared upload form contains final cards and JSON restore.

An older saved draft with zero teams uses the published team list for score previews and adds it on explicit Update leaderboard or Resume my saved results, preserving all raw scores and settings. Preview alone never writes storage. Customized teams are never automatically replaced: choose Use published team list in my draft and confirm replacement only if intended. Back up first. Notes and holds persist through localStorage, JSON, reports and publication exports. Only owner publication shares changes with everyone.

Known roster questions: Team 34 has Paddy Daly and Timothy Cummins only; Player 3 is explicitly vacant. Eugene McCrystal (away member at Bundoran) on Team 37 (Peter O'Keefe) is awaiting eligibility confirmation by Niall. No eligibility approval is asserted. Colin Owens appears on both Teams 10 and 37. Both workbook entries are preserved with score matching held until the committee resolves membership. His raw cards remain in Singles and unassigned review, but cannot count twice for teams. Correct or disambiguate the names consistently with score files, then clear the hold checkboxes. Notes record questions, not automatic eligibility exclusions.

Drafts are saved using localStorage on this origin. They do not sync across devices, browsers or hostnames. Corrupt stored data is preserved until explicit deletion/replacement. If storage is denied or full, changes remain in memory and a warning tells you to download a backup immediately. Clearing browser data removes drafts. This is not authentication or secure storage.

Owner publication: actual steps

  1. Obtain committee-approved team and score CSV files. Confirm permission to publish every player's name. Choose Upload HandicapMaster results on the leaderboard. Team editing and backup/publication tools are under More > Committee tools. An existing draft is resumed on apply; customized teams are replaced only with confirmation.
  2. Preview imports, confirm dates and net Stableford scoring, apply to the draft, and review teams, unassigned cards, weekend cancellation flags, tie warnings and final assumptions.
  3. Download the draft backup and league and final HTML report. Review Singles separately in the app; it is not included in that report. Keep an owner-controlled copy. Choose Export validated publication JSON. This downloads published.json; it does not publish.
  4. In the owner's repository checkout, copy that reviewed file to data/published.json. Optionally use the validating helper: npm run publish:data -- "C:\explicit\path\reviewed.json". The explicit input path is required. The helper modifies only the local publication file, never commits or pushes.
  5. Review git diff -- data/published.json. The owner commits the reviewed change on a feature branch, pushes it, and merges the approved pull request into main. Alternatively, the owner can use GitHub's edit/upload UI for the existing data/published.json and open a pull request. Do not upload names until permission is confirmed.
  6. For initial deployment, the repository owner opens GitHub Settings, Pages, selects Deploy from a branch, chooses main and / (root), and saves. No build, dependencies, secret, access token or backend is needed. If the organisation requires approval for public Pages, the owner must obtain it.
  7. Wait for GitHub Pages deployment, then use Refresh published results and verify on another browser/device. The live app is https://enkelly-pac.github.io/BlainroeWinterLeague/ and the repository is enkelly-PAC/BlainroeWinterLeague. All app paths are relative to the project site root.

Public names warning: Published JSON, team names, individual player names, cards and reports can be read and downloaded by anyone with access to the site/repository. A public repository's git history can retain old names after deletion. Do not publish email addresses, contact details, private handicap records, identifiers or unapproved personal information. The app only permits the documented schema fields. Individual playing handicap is optional metadata; omit it if unnecessary.

For a correction, restore a backup or edit/import a corrected draft and repeat the owner publication steps. Browser storage deletion cannot retract published data or git history. There is deliberately no browser token entry or automatic GitHub mutation.

Local use and validation

With a current Node.js installation (Node 20 or later), run npm test. There is no dependency install. Run npm run serve and open http://127.0.0.1:8080. Stop the server with Ctrl+C. Set PORT to choose another port. The server is for local static preview only and binds to localhost. Opening index.html through file:// will not reliably load modules or publication JSON.

The club logo is included as blainroe-anni-logo.png in the root. The page hides an unavailable image and retains the text branding. No CDN, external font request, analytics or network processing service is used. PDF export loads its library and embedded fonts locally on demand.

Tests exercise the shared pure engine, CSV formats, state/restore validation, storage errors, import form draft isolation, safe report output, PDF view selection, grouped season totals, Unicode names and export failure recovery. Node syntax checks can be run with node --check app.js, node --check leaderboard-pdf.js, node --check core.js, node --check storage.js, node --check tools/publish.mjs and node --check tools/serve.mjs.

Export the leaderboard as a PDF

Choose Export leaderboard PDF beside the main upload button. This downloads an actual PDF of the visible published view or local draft, not a print dialog. To export saved local results, choose Resume my saved results first. Publication is never changed. Export snapshots the view when clicked and labels it published/provisional, saved DRAFT or unsaved DRAFT. It includes the actual qualifying results-through weekend, all teams and players, all imported weekends, current team points and raw player-card breakdowns. With no qualifying team matches, it exports an awaiting-results team list without invented ranks or totals. Without an available team list, export is disabled with an explanation.

The landscape report uses the club logo and Spirit Ford Wicklow branding, readable green/white striped tables, repeated headers and page numbers. A summary precedes detail groups of at most six weekends, rather than cramming up to 52 qualifying weekends into tiny columns. Cancelled/excluded weekends are labelled and not counted. Missing/vacant cards, held raw cards, discards, unresolved cutoff ties and team-list review flags are explained briefly. No admin controls are copied into the PDF.

Design references actually reviewed: Craig's Craig-Handover\WINTER LEAGUE 2025 - 2026 TEAM LIST R5.pdf and WINTER LEAGUE 2025 - 2025 TEAM LIST R5II.xlsm (Teams and Sheet1), the GOY app's js\app.js PDF export and event-key helpers, and the GOY, Gross and Nett PDFs in PublishResults\AfterNovemberMedal. This adapts their landscape club heading, player columns, combined totals, green headers and striped rows, without copying their scoring rules. The GOY app uses browser print, not a PDF library.

A true local download uses pinned pdfmake 0.2.20 and embedded Roboto fonts, loaded only on first export. There is no dependency install. Preserve vendor\NOTICE.txt, pdfmake-LICENSE.txt (MIT) and Roboto-LICENSE.txt (SIL OFL 1.1) when deploying. No scores leave the device. It needs no internet once the static app and PDF assets are available locally; there is no offline service-worker installation.

Registration and score imports

  • New teams require 3 named players. Existing Team 34 alone may retain 2 with Player 3 vacant. Team names are unique. Duplicate player names are rejected unless every affected team explicitly holds that name's score matching; held names contribute zero to team scoring and final cards for held players are rejected. Matching ignores case, accents and punctuation, and treats a quoted surname-first name such as "Surname, Given" as Given Surname. Namesakes and initials require committee-disambiguated, consistently used names. Do not conflate two different people.
  • Team CSV header: Team Name,Player1,Player2,Player3 (also Team, spaces and case are accepted). Download draft team list CSV includes optional Notes,Held Players columns for spreadsheet editing; use | between multiple held names. Blank Player3 is valid only for Team 34. Preview and confirm whole-team-list replacement, including the removed-team list. Raw scores and settings remain unchanged. Basic four-column imports preserve notes/holds for matching team names; explicit Notes/Held Players columns replace them. Duplicated names require holds in the CSV itself. Empty header-only templates are still available.
  • Score CSV header: Player,Score,Handicap, with optional Handicap. Numeric net Stableford points, including zero, are accepted. Handicap Master CSV can contain metadata lines with Played on,07/11/2026 and a header Position,Name,Score (Play H'cap) with a cell 42 pts (10). Signed/plus handicaps are metadata only. The parser accepts explicit ISO, day/month/year, or full named-month dates in Played on / Date metadata. It never supplies today's date.
  • For the full Handicap Master export, choose Competition Report (Aggregated Net Result), identified by Aggregated Results - Net Scores. Its Overall Position header has an unnamed player column and Score (Play H'cap) values such as 29 pts (07) or 24 pts (-01). Overall Winners, division headings, repeated headers and report footers are handled without treating them as cards. Explicit No Return/withdrawn and disqualified rows (even DQ rows showing points) are omitted, with counts in the preview. No scores are invented for omitted cards. A reported card count must match the result rows, or the import is rejected as incomplete.
  • Competition Scorecards and Hole by Hole scores returned exports can accompany net reports in the same selection. They are recognized by their CSV contents, listed and excluded from net scoring, not stored. Their summary contains gross strokes, PU, missing holes and NR, not authoritative Winter League net points. Selecting only gross scorecards asks you to add the Aggregated Net Result report. Unknown or malformed result files still block the entire net batch. Keep scorecard originals privately for a future separate Winter Eclectic Cup; that competition is not implemented here and retaining files is not approval to publish them. No hole-to-points conversion is performed.
  • Quoted CSV cells, embedded doubled quotes, UTF-8 BOM, CRLF and surname-first names are supported. Only comma-separated CSV is supported, not Excel, HTML or semicolon exports. Outside the recognised aggregated report, non-score footers, blank/NR/withdrawn cards, stroke/medal/gross headers or invalid values are rejected with errors. Omit non-cards, rather than replacing them with invented points. A generic Score header cannot prove the competition format, so the uploader must explicitly confirm net Stableford.
  • Each score preview requires an explicit Saturday/Sunday weekend date, a round name and qualifying flag. Sunday dates map to Saturday so both days count once. An aggregated report naming both Saturday and Sunday is assigned their common Saturday key; dates from different weekends are rejected. Printed dates are ignored. If any file has no metadata date or play took place outside the weekend, the date remains blank and you must enter the committee-assigned weekend explicitly.
  • At most 2 MB per file and 20 files per score preview. The combined draft also has a 2 MB serialized backup limit so an exported backup is always restorable. Multiple files must belong to one weekend. Different players merge. Identical repeated cards are deduplicated, never counted twice. Conflicting repeated scores fail without changes. For corrections choose one correct card per player in a complete corrected CSV, use Replace entire weekend, and confirm removal of all old cards. Never silently append a duplicate card.
  • Scores before teams are permitted and displayed as unassigned. A later team import attaches canonical name matches automatically. Review unassigned cards for spelling mistakes. This Winter League uses reported 12-hole net Stableford points unchanged. Do not rescale them to 18 holes or apply handicap/two-thirds conversions. The app does not assume a fixed set of holes across the winter.
  • Edit round metadata or exclude/cancel/remove a weekend in Committee tools. Date collisions are rejected. Cancellation removes that entire weekend from every team's common schedule; exclusion preserves raw cards but contributes no points. Removal deletes its cards after confirmation. Existing final cards can prevent an edit that would invalidate final eligibility; back up and explicitly remove final cards before changing qualification.

Singles leaderboard

Singles shows all imported individual 12-hole net Stableford cards for one selectable weekend, including zero-point submitted cards and unassigned players before registration. Matching team membership appears after registration. No absent cards are invented, and team best-two scoring and discards do not apply to individuals. This is not a cumulative singles championship.

The default is the latest qualifying, noncanceled imported weekend, falling back to the latest imported weekend if none is active. All imported weekends remain selectable with their round name, Saturday weekend date and qualifying, excluded or canceled status. Canceled and excluded results are prominently labeled historical review only, not active official standings. Selection only changes this view, not imported state, and is retained across ordinary renders while that date exists. Published results and local drafts remain isolated.

Higher points rank first. Equal points share competition rank (1, 1, 3). Official singles countback is not available from imported numeric fields; alphabetical display within ties does not resolve them. The league and final HTML report is unchanged and does not include Singles; review this tab separately before publication.

League calculation and ties

All registered teams appear, even with no cards. This Winter League is a 12-hole net Stableford competition. For every common active qualifying weekend, the best 2 reported scores from 3 distinct players count unchanged. All three individual cards are retained and displayed under Teams and weekends; for example, 29, 24 and 20 contribute a team weekly total of 53 without deleting the 20-point card or rescaling any points to 18 holes. Missing cards contribute zero, including a completely missed weekend. Individual cards are already net Stableford. This weekly rule does not settle the separate final scoring assumption.

Default maximum is 10 qualifying weekends and 2 discards. The maximum is configurable from 1 to 52; discard count must be a whole number less than the maximum. Excess qualifying weekends are rejected, not silently truncated. A canceled/excluded weekend does not use a qualifying slot.

While live, all weekends count and the table is provisional. Only the explicit Qualification complete setting applies the worst 2 (or committee-selected number) of team weekend totals to the common schedule. For a short completed schedule, discards are clamped to keep at least one weekend if any are played. Completion requires at least one qualifying weekend.

The everyday leaderboard shows team points (retained totals) and each weekend's points, with discarded weekends marked after completion. Detailed raw/retained/discarded totals remain in the downloadable report. Equal worst rounds are discarded earliest first for deterministic display, without affecting totals or tie resolution.

Committee assumption: On equal retained totals, compare discarded team weekend scores in descending order (best discarded first, then next best). This is a lexicographic comparison, not a comparison of the smallest discarded score. If still equal, teams share competition rank. Alphabetical display within a tied group is not a tie-break.

Top 16 status is provisional before completion. If a tied group crosses place 16, no teams are claimed confirmed qualified and final imports are blocked. The committee must confirm a sporting tie resolution/interpretation and publish the accurate corrected state, not arbitrarily change points. This version deliberately provides no undocumented manual rank override. Unresolved first place is separately flagged. If fewer than 16 teams are registered and the cutoff is clear, all are eligible after completion.

Final: separate competition

No points carry over from the league. Final uploads are rejected until qualification is complete and the cutoff is resolved. There is no invented fixed final date because the source email year needs confirmation; an optional confirmed ISO date can be entered.

Download the eligible final template from the Final tab. It contains registered players on qualifying teams with blank scores, never automatic final results. Held names are omitted until resolved. Each row must have Team,Player,Total,Back9,Back6,Back3,Back1. One card per distinct registered player is allowed, and both team and membership must match registration. Total is a whole net Stableford score from 0 to 300 (the same validation range as league cards); countback values are finite, nonnegative and monotonic: Total >= Back9 >= Back6 >= Back3 >= Back1.

Final total needs committee confirmation: Default team final total uses the best 2 of 3 cards to mirror the league. The provided rules explicitly require all 3 cards for countback but do not unambiguously specify the final team total. The committee can explicitly select Sum all 3 in settings. Every final view and report identifies the selected interpretation.

Regardless of the total setting, all 3 player cards are required for a ranked team. Incomplete teams are shown as unranked, with a pending total. Ties compare final total, then the sum across all 3 players of Back9, Back6, Back3 and Back1, in order. Identical countbacks share rank. Final import replaces the entire final card list after confirmation; partial submissions are allowed but remain unranked.

Backup and schema

The same version 1 validator is used by published fetch, JSON restore, publication helper and imports. Unsupported versions/fields, invalid settings, duplicate canonical names/cards, excess rounds, invalid scores, dates or final eligibility are rejected before changes are applied. A backup includes settings, teams, raw rounds and optional final. JSON restore requires preview and explicit full-draft replacement.

{
  "version": 1,
  "settings": { "maxRounds": 10, "discardCount": 2,
    "complete": false, "finalScoring": "best2" },
  "teams": [],
  "rounds": [],
  "final": null
}

Team object: { name, players: [name1, name2, name3], notes?, heldPlayers? }. Notes is a string of up to 160 characters; heldPlayers is an array of named members whose score matching is held. Both fields are optional, so older version 1 backups still load. Team 34 may have only two players. Weekend object: { date: "YYYY-MM-DD", name, qualifying: true, canceled: false, cards: [{ player, score, handicap? }] }. Final object: { date: null or "YYYY-MM-DD", cards: [{ team, player, total, back9, back6, back3, back1 }] }. The question mark denotes an optional field, not part of its name.

Imported text is rendered through DOM textContent. Downloaded standalone HTML reports escape imported text and include a restrictive CSP. They do not execute scripts. The app also uses a strict self-only CSP, with no inline script/style handlers. JSON downloads are data, not server publication.
